### 1. Persistent per-user workspaces

Create a real backend workspace for every user/session.

* Store the workspace on the server filesystem.
* Files and folders must persist between runs and sessions.
* Existing CodeForge file explorer must read/write this real filesystem.
* Support create, edit, save, rename, delete, move files and folders.
* Prevent `../` path traversal and access outside the workspace.
* Add workspace initialization automatically.
* Existing projects/files must continue working.

### 2. Real interactive terminal

Replace any simulated terminal behavior with a genuine PTY.

Use `node-pty` + WebSocket.

The terminal must execute real commands in the user's workspace and preserve its current working directory.

It must support:

* interactive commands
* `cd`, `ls`, `pwd`, `mkdir`, `rm`, `cp`, `mv`, `cat`
* `python3`
* `python3 -m venv .venv`
* `source .venv/bin/activate`
* `pip install`
* `node`, `npm`, `npx`
* `git`
* available system compilers/interpreters

It must correctly support:

* `input()`
* Ctrl+C
* Ctrl+D
* Ctrl+L
* arrow keys
* Backspace
* Tab
* ANSI colors
* continuous output
* interactive programs
* terminal resizing
* multiple terminal sessions/tabs

Example that must genuinely work:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install requests
python3
```

Then:

```python
name = input("Name: ")
print("Hello", name)
```

### 3. Synchronize the entire IDE

Connect the existing:

**File Explorer ↔ Monaco Editor ↔ Terminal ↔ Run system**

to the same persistent workspace.

Changes made in the editor must immediately save to the backend filesystem.

Changes made from the terminal must appear in the file explorer.

Support at minimum:

```bash

node main.js
g++ main.cpp -o main && ./main
javac Main.java && java Main
```

* Never expose the host filesystem.
* Restrict every command to the user's workspace.
* Block path traversal.
* Do not expose server secrets/environment variables.
* Add reasonable CPU, memory, process and disk limits.
* Clean up orphaned processes.
* Do not use fake terminal output or mock filesystem data.
